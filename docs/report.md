# 实训报告：AI提示词管理系统开发

## 一、项目概述

本次实训项目基于 Next.js 14 + Flask + Supabase 技术栈，开发了一套提示词管理系统。系统包含前端展示层、后端 API 层和云端数据库，实现了提示词的增删改查、收藏、多标签、主题切换等功能，满足居家实训考核的各项要求。

## 二、技术栈选择

### 前端技术栈
- **Next.js 14**: 选用 App Router 模式，支持服务器组件和客户端组件混合使用，构建现代化单页应用。
- **TypeScript**: 提供类型安全，减少运行时错误，提升代码可维护性。
- **React Context**: 用于全局主题状态管理，实现主题切换和持久化。
- **CSS Variables**: 实现5套马卡龙主题配色，通过 CSS 变量动态切换。

### 后端技术栈
- **Flask**: 轻量级 Python Web 框架，快速构建 RESTful API。
- **Supabase**: 开源 Firebase 替代品，提供 PostgreSQL 数据库和认证服务。
- **Flask-CORS**: 解决跨域问题，支持前后端分离开发。

## 三、核心功能实现

### 1. 前端报错解决

在项目初期遇到了 TSX 语法解析错误：`Expected '>', got 'ident'`。经分析发现问题出在 `app/useTheme.ts` 文件中——该文件以 `.ts` 为后缀，但包含了 JSX 代码（`<ThemeContext.Provider>`）。

**解决方案**：
- 创建 `app/ThemeProvider.tsx` 文件，将所有包含 JSX 的组件代码移到该文件中
- 重写 `app/useTheme.ts` 为纯 TypeScript 文件，只导出 useTheme hook
- 更新 `app/layout.tsx` 正确引入 ThemeProvider

这是一个典型的 Next.js 14 App Router 规范问题，必须严格区分 `.ts` 和 `.tsx` 文件的用途。

### 2. 提示词 CRUD 功能

**前端实现**：
- 使用 fetch API 调用后端接口
- 封装统一的 API 调用函数（`lib/api/prompts.ts`）
- 使用 React hooks 管理列表状态和分页

**后端实现**：
- 基于 Flask 实现 RESTful API
- 使用 Supabase Python SDK 操作数据库
- 添加统一异常处理和标准化响应格式

### 3. 收藏功能

- 在数据库表中添加 `is_starred` 字段（boolean 类型，默认 false）
- 前端点击星星图标切换收藏状态
- 后端提供专门的 `/star` 接口处理收藏切换
- 收藏页面只查询 `is_starred=true` 的数据

### 4. 多标签功能

- 在数据库表中添加 `tags` 字段（text[] 数组类型，默认空数组）
- 前端表单支持逗号分隔输入标签
- 卡片组件渲染标签列表
- 搜索功能支持按标签筛选

### 5. 主题切换功能

- 定义5套马卡龙主题配色（粉、蓝、薄荷绿、奶黄、薰衣草紫）
- 使用 React Context 管理主题状态
- 通过 CSS Variables 注入全局样式
- 主题切换后自动持久化到 localStorage

### 6. 一键复制功能

- 使用 `navigator.clipboard.writeText()` API 实现复制
- 复制成功后显示"已复制"提示（2秒后消失）
- 提供降级方案（手动复制提示）

## 四、前后端联调

### 接口设计原则

1. **统一返回格式**: 所有接口返回 `{ code, message, data, error }` 结构
2. **RESTful 规范**: 使用标准 HTTP 方法（GET/POST/PUT/DELETE）
3. **参数校验**: 前端和后端都进行参数校验
4. **异常处理**: 后端统一捕获异常，返回错误信息

### 联调过程中的问题

1. **跨域问题**: 通过 Flask-CORS 中间件解决
2. **数据类型不匹配**: 确保前后端字段类型一致
3. **API 响应格式变化**: 更新前端 API 调用以适配新的响应格式

## 五、工程规范学习心得

### 1. Git 版本控制

- 分阶段提交代码，每个功能模块独立提交
- 使用 feat/fix/docs 等前缀标识提交类型
- 提交信息清晰描述变更内容

### 2. 环境配置管理

- 使用 `.env` 文件管理敏感配置
- 创建 `.env.example` 模板文件
- 在 `.gitignore` 中排除 `.env` 文件

### 3. 代码结构规范

- 组件化开发，提高代码复用性
- 类型定义集中管理
- API 调用封装为独立模块
- 样式使用 CSS 变量，便于主题切换

### 4. 异常处理规范

- 前端使用 try-catch 捕获异步操作异常
- 后端使用统一异常处理中间件
- 错误信息清晰、友好

## 六、项目部署

### 前端部署

使用 Vercel 一键部署：
1. 登录 Vercel 控制台
2. 选择 GitHub 仓库
3. 配置 Root Directory 为 frontend
4. 点击 Deploy 完成部署

### 后端部署

由于云端部署资源限制，后端采用本地运行方式。如需云端部署，可使用以下方案：
- **Vercel Serverless Functions**: 将 Flask 应用转换为 Serverless 函数
- **Render**: 支持 Python 应用部署
- **Heroku**: 传统 PaaS 平台
