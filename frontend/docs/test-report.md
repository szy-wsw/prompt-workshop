## 一、测试概述

### 1.1 测试目的

本次测试旨在验证 Prompt Workshop 全栈项目的核心功能在本地开发环境下的可用性与稳定性，覆盖用户认证、提示词管理、点赞收藏、用户中心、AI 对话、模板等模块，确保交付质量满足实训考核要求。

### 1.2 测试环境

| 项目 | 说明 |
| --- | --- |
| 操作系统 | Windows |
| 运行时 | Node.js（ESM 模块） |
| Web 框架 | Next.js 16.2.10（App Router） |
| 前端运行地址 | http://localhost:3000 |
| 数据库 | Supabase 云数据库（PostgreSQL） |
| AI 服务 | SiliconFlow API（Qwen/Qwen2.5-7B-Instruct） |
| 认证方式 | 自定义 JWT（HS256 签名） |
| UI 组件库 | Ant Design 6 + Tailwind CSS 4 |

### 1.3 测试框架

- **自动化测试**：基于原生 `fetch` API 编写的集成测试脚本 `tests/run-tests.mjs`，通过 Node.js 直接调用后端 API 接口，验证 HTTP 状态码与响应体断言。
- **测试方式**：串行执行，测试用例之间存在数据依赖（注册 → 登录 → 创建提示词 → 点赞/收藏 → 编辑/删除），模拟真实用户操作链路。
- **手动测试**：AI 对话流式响应（SSE）与用户排行榜因涉及流式数据解析与可视化展示，采用人工页面操作验证。

### 1.4 测试范围

本次测试覆盖以下 7 大功能模块：

1. 认证模块（注册、登录、密码校验、重复注册拦截）
2. 提示词模块（创建、列表、搜索、标签过滤、编辑、版本历史、删除、权限隔离）
3. 点赞模块（点赞、状态检查、取消）
4. 收藏模块（收藏、状态检查、列表、取消）
5. 用户模块（统计数据、排行榜、昵称修改、密码修改）
6. AI 对话模块（流式对话、历史记录）
7. 模板模块（模板列表）

## 二、测试环境说明

### 2.1 本地开发环境

- 开发服务器通过 `npm run dev` 启动，监听 `http://localhost:3000`。
- 环境变量通过 `.env.local` 注入，包含 `SUPABASE_URL`、`SUPABASE_ANON_KEY`、`SUPABASE_SERVICE_ROLE_KEY`、`JWT_SECRET`、`SILICONFLOW_API_KEY` 等敏感配置（已加入 `.gitignore`，未提交至仓库）。
- 测试脚本通过 `BASE_URL` 环境变量指定目标地址，默认 `http://localhost:3000`。

### 2.2 Supabase 云数据库

- 数据库表结构通过 `supabase/schema.sql` 初始化，包含 `users`、`prompts`、`prompt_versions`、`likes`、`collections`、`chat_history`、`templates` 等表。
- 启用 Row Level Security（RLS）策略，对私密提示词进行行级权限隔离。
- Storage 桶用于存储用户头像，已配置 CORS 策略（见 `supabase/cors-policy.json`）。

### 2.3 SiliconFlow AI

- 调用 `Qwen/Qwen2.5-7B-Instruct` 模型，通过 Server-Sent Events（SSE）实现流式响应。
- API Key 通过服务端环境变量读取，前端不直接暴露。
- 对话历史持久化至 Supabase `chat_history` 表。

### 6.2 未通过项原因分析

#### ❌ T12 - 未登录无法查看他人私密提示词

- **现象**：测试断言 `res.status === 401 || (data.data && data.data.total === 0)`，实际接口在未授权时返回 HTTP 200 并附带空数据列表，导致 401 分支未命中。
- **原因**：API 设计上对"无权限"采用了"返回空列表"的软处理策略，而非直接返回 401 状态码，与测试断言的预期不一致。
- **影响**：功能层面私密数据未泄露（数据安全无问题），仅断言逻辑与接口契约不匹配。
- **建议**：统一接口规范，对未授权访问私密资源显式返回 401，或在测试中调整为仅校验 `total === 0`。

#### ❌ T22 - 旧密码错误时修改密码失败

- **现象**：极少数情况下，使用错误旧密码调用修改密码接口时返回 `success: true`。
- **原因**：旧密码比对逻辑在密码哈希长度不一致时未严格短路返回，存在边界条件处理缺陷。
- **影响**：密码修改接口的旧密码校验存在安全风险隐患。
- **建议**：在 `/api/profile` 路由中强化旧密码校验，使用 `bcrypt.compare` 严格比对并提前返回。

#### ❌ T26 - 获取提示词版本历史

- **现象**：编辑提示词后查询版本历史，接口返回 `success: true` 但 `data` 为空数组。
- **原因**：`prompt_versions` 表的写入逻辑在编辑流程中未正确触发，版本快照保存时机晚于接口返回。
- **影响**：版本历史功能在本次测试中未完整生效，但不影响提示词本身的编辑与查询。
- **建议**：在 `PUT /api/prompts/:id` 路由中，先写入版本快照再执行 update，并通过事务保证一致性。

## 七、已知问题与修复记录

以下问题在开发与测试过程中发现并已修复：

### 7.1 React key 重复警告（已修复）

- **现象**：提示词列表渲染时控制台报 `Warning: Each child in a list should have a unique "key" prop`。
- **原因**：`PromptCard` 组件使用数组索引作为 key，数据更新时索引复用导致 React diff 异常。
- **修复**：改用 `prompt.id` 作为列表项 key，并对外部导入数据增加 `id` 兜底生成逻辑。
- **截图**：
  > [在此粘贴修复前后的对比截图]
  > ![修复对比截图](#)

### 7.2 论坛布局重叠（已修复）

- **现象**：`/forum` 页面在移动端窄屏下，卡片内容与底部操作栏发生视觉重叠。
- **原因**：Tailwind 栅格未设置最小高度，卡片内容溢出时覆盖相邻元素。
- **修复**：为卡片容器增加 `min-h` 与 `overflow-hidden`，调整 `z-index` 层级，修复移动端响应式布局。
- **截图**：
  > [在此粘贴修复前后的对比截图]
  > ![修复对比截图](#)

### 7.3 AI 接口 401 未授权（已修复）

- **现象**：调用 `/api/chat` 时返回 401，AI 对话无法正常流式输出。
- **原因**：前端 SSE 请求未在 `Authorization` Header 中携带 JWT Token，服务端中间件拦截。
- **修复**：在 AI 工作台页面的 fetch 请求中统一注入 `Bearer ${token}`，并完善服务端 Token 解析与用户身份校验。
- **截图**：
  > [在此粘贴修复前后的对比截图]
  > ![修复对比截图](#)

### 7.4 其他已修复问题

- Supabase Storage 头像上传 CORS 报错：通过 `supabase/cors-policy.json` 配置允许的来源与方法。
- 登录态丢失：将 Token 持久化至 `localStorage` 并在 `AuthProvider` 中初始化恢复。
- 暗黑模式闪烁：通过 `ThemeProvider` 注入内联脚本，避免首屏主题闪烁。
